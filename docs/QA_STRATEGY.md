# Проверка качества

## Уровни

**Проверка типов.** `npm run build` запускает `tsc -b` в строгом режиме, с
`noUncheckedIndexedAccess` и `noUnusedLocals`. Ошибка типов останавливает сборку.

**Модульные тесты.** Vitest. Покрывают расчёты: деньги, обязательства, разбор
банковской выписки. Это те места, где ошибка тихо портит данные и обнаруживается
через месяцы.

**Сквозные тесты.** Playwright, этап 11.

**Ручная проверка.** Приложение запускается и проходится по сценариям ниже.
Задача не выполнена, пока код лишь выглядит правильным.

## Что покрыто тестами сейчас

48 тестов в четырёх файлах.

`engine.test.ts` — длина серии привычки с пропусками и без отметки сегодня;
просроченная задача даёт критичный сигнал, а выполненная не даёт; задача
с тремя переносами замечается; закрытое обязательство молчит; цель без
движения замечается через две недели; проект без задач замечается, а
с задачами — нет; сигналы упорядочены по важности; у каждого есть
объяснение и раздел.

`ReviewMetrics.test.ts` — задачи считаются только внутри периода,
отменённые не считаются, просроченное с прежних периодов выносится
отдельно, возможные отметки равны числу привычек на число дней, перевод
не попадает в поток, цель без движения определяется по дате активности.

`calc.test.ts` — незаполненный остаток не равен нулю; кредитный лимит не входит
в собственные деньги; счёт, исключённый из доступных, не считается; перевод не
доход и не расход; возврат уменьшает расходы; расчётный остаток считается от
подтверждения; обязательство складывается из трёх частей; обязательство без сумм
не нулевой долг; свободные деньги могут быть отрицательными; сверка без
начального остатка не выдумывает расхождение.

`csv.test.ts` — даты `11.08.2026`, `2026-08-11`, `11/08/2026`; суммы
`1 234,56 ₽`, `-1234.56`, `1.234,56`, `1,234.56`; кавычки и удвоенные кавычки;
определение разделителя; раздельные столбцы прихода и расхода; отпечаток строки
устойчив к регистру и различает разные суммы; подсказка категории не подставляет
доходную категорию в расход.

## Сценарий по деньгам

```
Создать счёт с остатком
   ↓ остаток подтверждён, входит в сумму
Создать счёт без остатка
   ↓ показан как «не заполнен», в сумму не входит, шкала известного показывает пробел
Записать доход
   ↓ доходы месяца выросли, расчётный остаток вырос
Записать расход
   ↓ расходы месяца выросли, расчётный остаток уменьшился
Перевод между своими счетами
   ↓ доходы и расходы не изменились, остатки обоих счетов изменились
Обновить страницу
   ↓ все значения на месте
Изменить операцию
   ↓ пересчитано
Удалить операцию
   ↓ пересчитано
Выгрузить копию
   ↓ файл содержит все таблицы
Удалить данные, восстановить из копии
   ↓ значения совпадают с исходными
```

## Сценарий по обязательствам

```
Создать обязательство: тело 120 000, проценты 3 400
   ↓ «Я должен» показывает 123 400
Записать платёж 9 500, где тело 7 000, проценты 2 500
   ↓ сохраняется
Записать платёж 9 500, где части дают 9 000
   ↓ окно не закрывается, объясняет расхождение
```

## Сценарий по импорту выписки

```
Загрузить файл
   ↓ показано: распознано строк, пропущено, похоже на дубли, будет записано
Снять отметку со строки
   ↓ счётчик «будет записано» уменьшился
Импортировать
   ↓ отчёт с числом добавленных
Загрузить тот же файл повторно
   ↓ все строки помечены как возможные дубли и отключены
```

## Проверка интерфейса

Три ширины: настольная, планшет, телефон 375 пикселей.

На каждой: нет горизонтальной прокрутки; длинные суммы не обрезаются; текст не
налезает; модальное окно помещается по высоте; списки прокручиваются внутри
себя; наведение и фокус видны; пустое состояние объясняет, что делать; состояние
загрузки не прыгает.

Обе темы: нет светлых поверхностей в тёмной теме и наоборот; контраст текста
достаточен; границы видны.

## Что уже нашла ручная проверка

Запуск приложения выявил четыре дефекта, которых не видели ни типы, ни тесты:

1. Dexie запрещает запись внутри живого запроса. Подготовка первого запуска
   писала в базу из `useLiveQuery` и роняла всю оболочку. Исправлено:
   подготовка вынесена в отдельный эффект, живые запросы только читают.
2. `capitalize` в CSS писал дату как «11 Августа 2026». Заменено на
   `first-letter:uppercase`.
3. При отсутствии счетов подпись говорила «подтверждено по всем счетам».
   Заменено на «счетов ещё нет — сумма неизвестна».
4. Сумма `+143 750 ₽` обрезалась на экране 375 пикселей. Кегль показаний на
   узких экранах уменьшен.

Вывод, который стоит помнить: проверка типов и модульные тесты не заменяют
запуск приложения.

## Определение готовности

Изменение готово, когда: типы проходят, тесты проходят, сборка проходит,
приложение запущено и сценарий пройден руками на трёх ширинах в обеих темах, ни
одна кнопка не бездействует, ни одно число не выдумано, данные переживают
перезагрузку.
