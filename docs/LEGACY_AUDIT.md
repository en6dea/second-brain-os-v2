# Аудит прежней версии

Обследовано перед началом работы над второй версией. Источники: репозиторий
`en6dea/second-brain-oc` (локальная копия, ветка `main`, коммит `d1f05ea`),
файлы `PROJECT-CONTEXT.md`, `DATA-MODEL.md`, `NEXT-STEPS.md`, `ROLLBACK.md`,
код `app.js`, `app-cloud.js`, `app-life.js`, `app-charts.js` и папка `v2/`.

Прежний репозиторий не изменялся. Ни один файл в нём не тронут.

## Что это было

Личная операционная система без сборки и фреймворков: HTML, CSS и JavaScript,
подключённые напрямую. Версия `V115 · SWITCHABLE THEME`, схема данных 3.

Размеры файлов на момент аудита:

| Файл                   | Размер   | Назначение                                        |
| ---------------------- | -------- | ------------------------------------------------- |
| `app.js`               | 1 092 КБ | вся логика: маршруты, экраны, финансы, оформление |
| `styles-dark-base.css` | 577 КБ   | тёмная тема                                       |
| `styles.css`           | 560 КБ   | светлая тема                                      |
| `app-cloud.js`         | 27 КБ    | синхронизация, копии, PWA                         |
| `app-charts.js`        | 21 КБ    | графики                                           |
| `app-life.js`          | 15 КБ    | дополнительный слой                               |
| `v2/`                  | ~110 КБ  | начатая переработка на том же хранилище           |

`app.js` собран склейкой примерно тридцати прежних файлов. Границы отмечены
комментариями `/* ===== source: app-v104-full.js ===== */`. Найдено 11 таких
меток: `compat-v104`, встроенный сценарий из `index.html`, `v881-visual-inline`,
`v883-visual-icons`, `sbos-v8851-hotfix`, `app-v91-stability`,
`app-v93-assistant`, `app-v103-product`, `app-v104-full`,
`app-v108-information-actions`, `app-v112-finance-center`.

## Разделы

Список маршрутов взят из `CUSTOM_ROUTES` и функции разбора маршрута в `app.js`.

Основная навигация: главная (`today`), GameLife, цели, планер, разобрать
(`review-queue`), календарь, финансы, привычки, информация, архив, подсказчик,
настройки, профиль.

Финансы — вложенный раздел из семи страниц: сегодня (`finance`), счета и
резервы, план, операции, долги, календарь платежей, разбор недели.

Информация — папки с записями: люди, заметки, идеи, желания, документы, книги,
фильмы, поездки, пароли, личное, обучение.

Отдельные страницы: дневник подсознания, вишлист привычек, страница привычки,
страница цели, «Полина» и «неделя вдвоём», покупки, задачи, входящие.

## Чего в прежней версии не было

Проверено поиском по всем файлам: раздела для валютного рынка и торгового
журнала в приложении нет. Слово «сделка» встречается 9 раз и относится к другим
смыслам. Торговая аналитика живёт отдельным проектом на Python
(`forex-analysis`, подключение к терминалу) и с приложением не связана.

Значит, торговый журнал во второй версии строится с нуля, а не переносится.
Данных для переноса по нему нет.

## Модель данных

Полное состояние: IndexedDB, база `SecondBrainOSDurableStorage`, хранилище
`records`, ключ `main-state`. В `localStorage['secondBrainOS.v1']` лежит только
`schemaVersion` и `settings.storageGuard`. Копии — там же в `records` под
ключами `backup:*` и `daily:*`.

Коллекций 37. Основные: `tasks`, `inbox`, `goals`, `habits`, `habitWishlist`,
`discipline`, `gameLife`, `financeAccounts`, `operations`, `financeCategories`,
`financePlans`, `financeMonthBudgets`, `financeReservations`,
`financeWeeklyReviews`, `deferredPurchases`, `purchases`, `debts`,
`debtPayments`, `people`, `polinaDays`, `coupleActivities`, `notes`, `ideas`,
`documents`, `books`, `bookSessions`, `films`, `learningMaterials`,
`knowledgeLinks`, `personal`, `subconsciousEntries`, `wishes`, `trips`,
`archive`, `planTemplates`, `lifePlans`, `settings`.

### Правила, которые стоили дорого и должны сохраниться

1. Незаполненный остаток счёта (`actualBalance: null`) — не ноль. Молчаливый
   ноль создаёт ложную уверенность в том, сколько денег есть.
2. Платёж по долгу делится на тело, проценты и штрафы. Основной долг уменьшает
   только тело, поэтому срок погашения считается амортизацией.
3. Собственные деньги считаются отдельно от кредитных. Кредитный лимит не
   увеличивает количество собственных денег.
4. План не равен расходу. Операция создаётся только после действия «Провести».
5. Отметки привычек — словарь по датам, а не массив.
6. Перевод между своими счетами не доход и не расход.

Все шесть перенесены во вторую версию и закреплены тестами.

## Что мешало в интерфейсе

Боковое меню — плоский список из двенадцати пунктов без группировки: главная,
GameLife, цели, планер, разобрать, календарь, финансы, привычки, информация,
архив, подсказчик, настройки. Рядом дублирующие вкладки в шапке и ещё одно меню
внизу для телефона. Три разных навигации на один и тот же набор разделов.

Иконки заданы текстовыми символами прямо в разметке: `⌂`, `✦`, `🎯`, `▦`, `₽`,
`✓`, `i`, `▣`, `⚙`. Выглядят по-разному в разных системах и не масштабируются.

«Информация» работает как файловый ящик: одиннадцать папок, между которыми
записи не связаны. Заметка о книге и сама книга лежат в разных папках и друг о
друге не знают.

Слой GameLife с опытом, монетами и уровнями существует рядом с целями, но с
ними не связан. Цифры этого слоя не выводятся из работы человека.

## Технический долг

Один файл на 1 МБ и 25 тысяч строк. Границы прежних версий отмечены только
комментариями, порядок исполнения слоёв значим, а зависимости между ними не
описаны. Поиск нужного места ведётся по меткам источника.

Две таблицы стилей по полмегабайта, различающиеся только значениями цветов.
Тёмная собирается из светлой скриптом на Python; правки в готовом файле теряются
при следующей сборке. Прежний контекст фиксирует 179 переменных в 11
конкурирующих блоках `:root`.

Состояние — одна глобальная переменная `state`, доступная всему коду. Отрисовка
идёт заменой `innerHTML` целиком, обработчики навешиваются делегированием по
атрибутам `data-v78-action`. Маршрутизация — на `hashchange` с пятью
независимыми подписчиками, каждый со своей задержкой (10, 15, 40, 60 мс).

Разметка собирается конкатенацией строк. Экранирование делает функция `safe`,
и её вызов зависит от внимательности автора в каждом месте.

Проверки типов нет. Тестов нет. Проверка изменений — ручной обход разделов.

Обновление версии выполняется правкой строки `?v=` сразу в трёх файлах
командой `sed`. Забытый файл даёт две копии кода в одном браузере: одна рисует
экран, другая пишет данные.

## Начатая переработка в папке `v2/`

Одиннадцать экранов на том же хранилище, чистые функции расчётов, отдельный
слой форм. Направление верное, и вторая версия наследует его решения: расчёты
без обращения к базе, копия перед первой записью, пустое числовое поле как
`null`, а не ноль.

Ограничения, из-за которых работа не была продолжена: сборки нет, поэтому
версии приходится проставлять вручную в каждом импорте; типов нет; облачная
синхронизация работает только со старым приложением; поиск и напоминания не
перенесены.

## Что из этого следует для второй версии

Сохранить: все функциональные направления, шесть правил учёта денег, формат
отметок привычек, разделение личных записей и остальных данных.

Изменить: плоское меню на группы по вопросам, а не по сущностям; один файл на
модули по возможностям; строковую разметку на компоненты с проверкой типов;
две таблицы стилей на один набор токенов с двумя темами; ручной обход разделов
на тесты и проверку типов в непрерывной сборке.

Не переносить: слой GameLife в прежнем виде. Его цифры не выводятся из данных,
а вторая версия показывает только то, что посчитано из записей.
