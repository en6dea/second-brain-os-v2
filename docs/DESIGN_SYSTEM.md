# Дизайн-система Daylight Observatory

## Направление

Daylight Observatory («Дневная обсерватория») — визуальная реализация
«Тихого интеллекта». Это взрослая личная система с жемчужными минеральными
поверхностями, точной типографикой и медленным живым светом. В тёмной теме та
же материальность становится глубокой вечерней синевой. Не игровая панель,
не трекер с наградами и не набор разноцветных плиток. Показания читаются без
усилия, а границы знания остаются видимыми.

Отправная точка — главное правило продукта: незаполненное не равно нулю. Обычное
финансовое приложение прячет пробел в данных за нулём. Здесь пробел показан.
Отсюда взялась и подпись системы, и типографика, и палитра. Доступны светлая,
тёмная темы и режим «как в системе»; структура и значения между ними не меняются.

## Подпись системы: шкала известного

Под сводными показателями идёт тонкая шкала. Сплошной отрезок цвета акцента —
то, что подтверждено. Штриховка — то, что системе неизвестно. Рядом числа:
«известно 2», «не заполнено 1».

```
Собственные деньги
99 200 ₽
не заполнено: Вклад
▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀░░░░░░░░
известно 2          не заполнено 1
```

Компонент `ШкалаИзвестного` в `src/design-system/components/Data.tsx`.
Штриховка задана токеном `--hatch`, чтобы выглядеть одинаково везде.

## Палитра

Дневная база — минеральный `#edf3f6`, вечерняя — глубокий синий `#0b1323`.
Карточки не становятся отдельными белыми или чёрными прямоугольниками: глубина
строится небольшим шагом яркости, тонкой холодной границей и локальным светом.
Акцент — преломлённый голубой свет; он обозначает
действие и подтверждённое, а не раскрашивает весь экран.

| Токен                 | Смысл                                       |
| --------------------- | ------------------------------------------- |
| `--surface-bg`        | фон окна, дневное значение `#edf3f6`        |
| `--surface-sidebar`   | поверхность боковой навигации               |
| `--surface-card`      | основная поверхность                        |
| `--surface-card-deep` | более глубокий слой карточки                |
| `--surface-raised`    | приподнятая интерактивная поверхность       |
| `--surface-over`      | диалог и поверхность над контентом          |
| `--surface-sunken`    | утопленная область, поле, дорожка прогресса |
| `--surface-hover`     | короткий отклик поверхности                 |
| `--line-soft`         | обычная граница                             |
| `--line-strong`       | заметная граница и состояние фокуса         |
| `--ink`               | основной текст                              |
| `--ink-2`             | пояснение                                   |
| `--ink-3`             | подпись, единица, источник                  |

| `--know`              | знание, личное                              |

Смысловые цвета применяются только по смыслу. Приложение не раскрашивается.

### Контраст текста

Все три ступени текста проходят WCAG AA (4.5:1) на всех текстовых поверхностях
обеих тем. Это не глазомер: `npm run check:contrast` читает значения
прямо из `src/index.css` и считает по формуле. Проверка стоит в CI.

`--ink-3` — цвет подписи-источника под числом. Именно им напечатано объяснение,
откуда взялась цифра, поэтому его читаемость — не оформление, а часть правила
«ни одной выдуманной цифры».

При изменении палитры `--ink-2` и `--ink-3` проверяются вместе: если сдвинуть
только третью ступень, она сливается со второй, и три уровня текста превращаются
в два.

## Шрифты

Один шрифт — Manrope. Иерархия строится начертанием, размером, интервалом и
контрастом, без смешения гарнитур. Для класса `.tnum` включаются табличные цифры
через `font-variant-numeric`: суммы в столбцах не смещаются при изменении, но
остаются частью единого голоса интерфейса.

## Шкала размеров

Размер текста задаётся ролью, а не числом. Семь ступеней в `@theme inline`
внутри `src/index.css`:

| Класс          | Размер | Роль                             |
| -------------- | ------ | -------------------------------- |
| `text-micro`   | 11px   | единица над числом, `kbd`        |
| `text-caption` | 12px   | метаданные, надзаголовок раздела |
| `text-meta`    | 14px   | вторичный текст                  |
| `text-body`    | 16px   | основной текст интерфейса        |
| `text-h3`      | 20px   | заголовок карточки               |
| `text-h2`      | 24px   | заголовок раздела                |
| `text-h1`      | 32px   | заголовок экрана                 |

Размер значка нельзя выразить токеном CSS: у lucide это число в разметке.
Ступени лежат в `src/design-system/iconSize.ts` — `ЗНАЧОК.подпись` (12),
`.строка` (14), `.основной` (16), `.крупный` (18), `.показание` (20).

До шкалы в коде было 19 размеров текста (включая шаг в полпикселя: 12 и 12.5,
13 и 13.5) и 11 размеров значка. Разница между соседними значениями не несла
смысла — каждый экран подбирал число заново.

Перевод идёт постепенно: `npm run check:scale` считает оставшиеся произвольные
`text-[Npx]`, `rounded-[Npx]` и `size={N}` и падает, если их стало больше.
Ноля не требуется — требуется, чтобы счётчик не рос. Когда он падает, база в
`scripts/check-scale.mjs` опускается следом.

Исключение, оставленное намеренно: `rounded-[4px]` у столбиков недельного
графика привычек. Столбик узкий, ближайший общий токен съедает его форму.

## Структурный приём: единица измерения

Над показанием стоит надзаголовок с единицей: `₽ · ОСТАТОК`, `ШТ · ЗАДАЧИ`,
`₽ · ЗА МЕСЯЦ`. Он кодирует, что именно меряет число.

Нумерация вида «01 / 02 / 03» не используется. Она уместна только там, где
порядок несёт смысл: в шагах импорта выписки. Там она и стоит.

## Радиусы, тени, движение

Радиусы сдержанные: поверхность выглядит архитектурной, а не игрушечной. Тени
короткие и тёмные; глубину чаще создают граница, разница поверхностей и локальное
свечение, а не эффект парящей белой карточки.

Движение собрано в один спокойный ритм. Экран раскрывается коротко, крупные блоки
входят с небольшим шагом, интерактивная поверхность отвечает смещением на один
пиксель и изменением света. Шкала известного прочерчивается слева направо.
Абстрактное фоновое свечение движется медленно и остаётся на границе восприятия;
постоянно дрейфующих предметных значков, конфетти и игровой пульсации нет.

Событийные эффекты проигрываются один раз и показывают результат действия.
`prefers-reduced-motion` убирает декоративное движение, сокращает переходы до
мгновенных и никогда не задерживает появление итогового значения.

## Компоненты

`Кнопка`, `КнопкаИконка`, `Карта`, `ШапкаКарты`, `ТелоКарты`,
`ЗаголовокРаздела`, `Значок`, `Метрика`, `ШкалаИзвестного`, `Полоса`, `Пусто`,
`Загрузка`, `Ошибка`, `Поле`, `Ввод`, `ТекстМного`, `Выбор`, `ВводСуммы`,
`Переключатель`, `Сегменты`, `Окно`.

`ВводСуммы` работает в рублях, наружу отдаёт копейки, пустое поле возвращает
`null`. `Метрика` требует подпись-источник: число без объяснения происхождения не
показывается.

## Правило для новых экранов

Литеральных цветов в компонентах нет. Только токены. Если нужного оттенка нет,
он добавляется в `src/index.css` с именем по смыслу, а не по виду.

То же правило действует для размера текста, радиуса и размера значка: класс из
шкалы, а не число в квадратных скобках. Нужной ступени нет — она обсуждается и
добавляется в шкалу, а не подбирается на глаз в одном экране.

Интерактивный элемент имеет зону касания не меньше 44 пикселей, даже если его
видимая метка или значок меньше.

Новый экран должен выглядеть так, будто был частью системы с самого начала.

## Тексты

Кнопка называет то, что произойдёт: «Сохранить», а не «Отправить». Действие
сохраняет имя на всём пути: кнопка «Записать платёж» даёт сообщение «Платёж
записан».

Пустое состояние объясняет, что делать. Ошибка говорит, что случилось и как
починить, без извинений. Незаполненное показывается как «не заполнено», а не как
«0».
