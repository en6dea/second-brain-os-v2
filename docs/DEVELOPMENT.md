# Второй мозг 2.0 — документ разработки

Единая точка входа в проект. Собирает в одном месте то, что раньше было
разбросано по восьми документам: что за продукт, на чём построен, как устроены
данные, что уже готово и что осталось. Подробности каждой темы — в отдельных
документах из раздела [Куда идти дальше](#куда-идти-дальше); правила работы
для Claude Code — в [`CLAUDE.md`](../CLAUDE.md).

Версия на момент записи: `2.0.0-alpha.1`.

## Что за продукт

Личная операционная система одного человека: день, цели, привычки, деньги,
знания, обзоры. Работает в браузере без сервера, все данные — на устройстве
владельца.

Первая версия (`en6dea/second-brain-oc`) отвечала на вопрос «где я это
записал». Эта версия отвечает на другой: «что мне сейчас делать и в каком я
положении». Прежний репозиторий продолжает работать независимо, его нельзя
менять — см. «Запрет на прежний репозиторий» в `CLAUDE.md`.

Круг работы, вокруг которого построен продукт:

```
Записать → Понять → Решить → Сделать → Увидеть результат → Разобрать → Изменить решение
```

Три обещания, которым подчинено всё остальное:

1. **Ни одной выдуманной цифры.** Каждое число посчитано из записей, рядом
   указан источник. Общего «показателя жизни» нет.
2. **Незаполненное не равно нулю.** `null` — «неизвестно», не участвует в
   суммах. Под сводными показателями — шкала известного (сплошная часть —
   подтверждено, штриховка — пробел).
3. **Ни одной мёртвой кнопки.** Рабочий на вид элемент работает. Для
   нерасписанного — честная заглушка с объяснением, что будет и на каком
   этапе.

Для кого: один человек, ведущий систему ежедневно. Не команда, не клиенты, не
совместная работа, не корпоративный учёт, не игра с наградами.

## Стек

React 19 + TypeScript (строгий режим) + Vite 8 + Tailwind 4. Данные — Dexie
(IndexedDB) в браузере, без сервера. Маршрутизация — React Router 7,
состояние — Zustand, формы — react-hook-form + zod, графики — Recharts, даты —
date-fns. Тесты — Vitest, линт — oxlint, форматирование — Prettier.

| Команда                | Что делает                        |
| ----------------------- | ---------------------------------- |
| `npm run dev`            | сервер разработки (`localhost:5173`) |
| `npm run build`          | проверка типов (`tsc -b`) и сборка |
| `npm run preview`        | просмотр собранного                |
| `npm test`                | модульные тесты (Vitest)          |
| `npm run lint`            | статическая проверка (oxlint)     |
| `npm run format`          | форматирование (Prettier)         |
| `npm run check:contrast`  | контраст текста по WCAG AA        |
| `npm run check:scale`     | соблюдение шкалы размеров         |
| `npm run check:tracked`   | что случайно попало в git         |

```

    layout/       AppShell, боковое меню, шапка, меню телефона
    router/       маршруты
    providers/    контексты приложения
    navigation.ts группы разделов бокового меню (ДОМЕНЫ)
    keyboard.ts   горячие клавиши, командное окно
  core/           предметная область без интерфейса
    db/           Dexie: схема, типы, репозиторий, идентификаторы
    money/        рубли и копейки, запись сумм
    calendar/     даты по-русски
    language/     склонения, запись чисел
    signals/      движок сигналов (что требует внимания сейчас)
    day/          «что делать сейчас» — одно действие с основаниями
    reminders/    расписание напоминаний из записей
    quick/        разбор команд быстрого ввода
    search/       общий поиск по разделам
    backup/       копии и восстановление (копияПередОпасным)
    migrations/   перенос из прежней версии (legacy.ts)
    sync/         договор синхронизации (ПоставщикСинхронизации)
    demo/         показательные данные
  design-system/  токены оформления и общие компоненты
  features/       22 раздела приложения, каждый со своей model/ и страницами
```

Разделы в `src/features/`: `dashboard`, `inbox`, `quick`, `calendar`, `goals`,
`tasks`, `projects`, `planning`, `planner`, `planned`, `habits`, `people`,
`experience`, `finance`, `obligations`, `trading`, `knowledge`, `learning`,
`journal`, `reviews`, `analytics`, `relationship`, `settings`.

Правила, за которыми стоит следить при добавлении кода — полный текст в
`CLAUDE.md`, коротко:

- Расчёты — чистые функции в `features/*/model/`, без обращения к базе;
  проверяются тестом.
- Каталогов `utils`, `helpers`, `common`, `shared` нет — имя модуля называет
  предметную область.
- Прикладная логика не знает о Firebase/облаке напрямую — только через
  `ПоставщикСинхронизации` из `src/core/sync/provider.ts`.
- Связи между сущностями — по идентификаторам, не копиями объектов.
- Файл длиннее 200 строк и функция длиннее 50 строк — повод разделить.

## Модель данных

IndexedDB, база `ВторойМозг2`, тридцать с лишним таблиц по одной на сущность
(полный список и инварианты — [`docs/DATA_MODEL.md`](DATA_MODEL.md)). В
`localStorage` не хранится ничего — включая тему: переключателя тем больше
нет, приложение всегда светлое.

Общее для всех записей: `id`, `createdAt`, `updatedAt`, необязательный
`legacy` (нераспознанные поля прежней версии, хранятся дословно, не
удаляются).

Деньги — целое число копеек, рубли только на границе ввода-вывода
(`src/core/money/Money.ts`). Ключевые денежные правила закреплены тестами в
`src/features/finance/model/calc.test.ts`:

- Незаполненный остаток счёта — не ноль, в суммы не входит.
- Кредитный лимит не входит в собственные деньги.
- Перевод между своими счетами — не доход и не расход.
- Обязательство = тело + проценты + штрафы, платёж делится на три части.
- Сверка без начального остатка не выдумывает расхождение.

Изменение схемы — только через `this.version(N).stores({...})` в `db.ts`,
без переименования полей без функции переноса, без удаления данных.

## Оформление

Направление — «Тихий интеллект»: спокойный, взрослый, точный. Токены —
`src/index.css`, компоненты — `src/design-system/`. Значки — семантический
цвет по сущности, не по странице (`design-system/components/Icon.tsx`).
Полностью — [`docs/DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md). Коротко:

- Акцент — лесной нефрит (`--accent`); смысловые цвета (`--good`, `--bad`,
  `--warn`, `--info`, `--know`) применяются только по смыслу.
- Один шрифт — Manrope. Табличные цифры включаются `font-variant-numeric`, а
  не отдельной гарнитурой.
- Шкала текста: 12, 14, 16, 20, 24, 32 плюс 11 на единицу над числом.
- Подпись системы — компонент «Шкала известного» (`design-system/components/Data.tsx`):
  сплошная часть — подтверждено, штриховка — неизвестно.
- Тема одна, светлая (переключателя нет и не было в этом смысле выбора —
  тёмная удалена целиком). Контраст текста проверяется автоматически
  (`npm run check:contrast`) — три ступени текста должны проходить WCAG AA
  на всех поверхностях.
- Минимальная зона касания — 44 пикселя.
- Шесть доменов навигации (Сегодня, Планы, Жизнь, Деньги, Знания, Система) —
  разделы внутри домена открываются полосой под заголовком, а не отдельным
  пунктом бокового меню.

## Перенос данных и синхронизация

Перенос из прежней версии — Настройки → «Перенос из прежней версии», код в
`src/core/migrations/legacy.ts`, подробно — [`docs/MIGRATION_PLAN.md`](MIGRATION_PLAN.md).
Четыре правила: исходный файл не меняется; перед записью — копия текущих
данных в файл; сначала предпросмотр, запись только после подтверждения;
нераспознанное поле сохраняется в `legacy`, а не выбрасывается.

Проверено на реальной выгрузке: 1897 операций, 27 обязательств, 42 записи
архива, отметки привычек из двух источников.

Облачная синхронизация — реализация поверх `ПоставщикСинхронизации` на
Firebase (`src/core/sync/FirebaseProvider.ts`), выключена по умолчанию и
работает только после того, как человек сам создал свой проект Firebase и
вписал его настройки в Настройки → «Синхронизация». Слияние — «побеждает
более поздняя правка» (`src/core/sync/merge.ts`), удаления передаются через
отдельную таблицу надгробий (хук на удаление в `db.ts`, а не правка каждого
места, где вызывается `.delete()`). Синхронизируется всё содержимое, кроме
настроек устройства (per-device) — `src/core/sync/privacy.ts`.
Firebase SDK не входит в основной пакет: подключается отдельным файлом,
который браузер скачивает, только когда синхронизация действительно
настроена.

## Что готово и что осталось

Все разделы построены, мёртвых заглушек в приложении нет. Полная карта —
[`docs/INFORMATION_ARCHITECTURE.md`](INFORMATION_ARCHITECTURE.md), план по
этапам — [`docs/ROADMAP.md`](ROADMAP.md). Кратко по крупным незакрытым
кускам:

- **Деньги** — готово: обзор, счета, операции, категории, бюджет, импорт
  выписки, сверка, обязательства с разделением платежа. Осталось: проведение
  плановых платежей, резервы под обязательства, календарь платежей, разбор
  недели, амортизация долга с графиком погашения.
- **Быстрый ввод** (`/quick`) — команда одной строкой через адрес, для ввода с
  телефона в обход форм: `src/core/quick/`. Уведомления браузера о платежах,
  задачах и привычках — `src/core/reminders/`, включаются в настройках,
  работают, только пока вкладка открыта — настоящего push с сервера нет.
- **Сигналы и автоматизация** — движок сигналов (`src/core/signals/engine.ts`
  + `rules/`) виден не только на Главной: компактная полоска
  (`src/features/signals/`) на Финансах, Целях, Привычках, Людях и
  Отношениях. Повторяющиеся задачи (`Задача.повтор`) и периодичность платежа
  по обязательству (`Обязательство.повторПлатежа`) реально создают следующую
  задачу и сдвигают дату — раньше оба поля существовали в схеме, но их
  никто не читал. В Финансах — прогноз темпа трат до конца периода
  (`finance/model/SpendingPace.ts`). В Обзорах — слой «что повторяется»
  (`reviews/model/Patterns.ts`): сравнение месяцев между собой, честный порог
  в 4 месяца истории до первого вывода.
- **Перенос и облако** — перенос из прежней версии готов. Синхронизация на
  Firebase проверена вживую на настоящем проекте: подключение, вход, первая
  отправка записей в Firestore. Синхронизируется всё содержимое без
  исключений по смыслу — кроме настроек устройства (`src/core/sync/privacy.ts`).
  Не проверена вживую передача между двумя разными устройствами
  одновременно. Ручного разрешения конфликтов в интерфейсе нет — работает
  только автоматическое «побеждает более поздняя правка».
- **Пароли** — новый раздел, `src/features/passwords/`. Шифруется
  мастер-паролем (PBKDF2 + AES-GCM), ключ живёт только в памяти. Забытый
  мастер-пароль не восстановить.
- **Цели** — вехи (`Цель.вехи`) теперь можно добавлять в интерфейсе;
  раньше поле существовало в схеме, но правило «ближайшая веха — что
  делать сейчас» (`core/day/NextAction.ts`) и критерий достижимости в
  SmartReview были мертвы за неимением данных.
- **GameLife** — честная версия в `src/features/gamelife/`: уровень и очки
  считаются из реальных действий (задачи, привычки, цели, обзоры), веса
  открыты в интерфейсе. Прежний ГеймЛайф не перенесён из первой версии
  осознанно — его цифры не выводились из данных.
- **Проверка** — сквозные тесты (Playwright) ещё не написаны, это отдельный
  этап (см. `docs/QA_STRATEGY.md`).
- **Знания** — на будущее: обратные ссылки между записями и разметка текста.
- **Торговля** — на будущее: снимки экрана сделок и раздел обучения с
  программой.
- **Осталось из крупного** (см. историю сессии): в Планировании
  `План.целиId`/`вызовId` не заполняются формой, в Планере нет моста
  «замысел → задача», в Опыте и вызовах `Вызов.завершён` никогда не
  становится `true`, в Привычках `частота`/`дниНедели`/`разВНеделю` не
  редактируются, в Финансах не используется `Обязательство.ставкаГодовых`
  и нет порядка погашения долгов.

Версии: `2.0.0-alpha.1` — текущая, все разделы построены, деньги и перенос
частично. `2.0.0-beta.1` — после оставшегося в деньгах и облачной
синхронизации. `2.0.0` — после сквозных тестов.

## Проверка перед тем, как считать изменение готовым

```bash
npm run build   # типы и сборка
npm test        # модульные тесты
npm run lint
```

Этого недостаточно — обязательна ручная проверка сценария в запущенном
приложении на трёх ширинах экрана (телефон, планшет, десктоп). Автоматика уже
пропускала ошибки, которые находила только ручная проверка: запись внутри
живого запроса Dexie, `capitalize` на дате, обрезанную сумму на телефоне.

Изменение готово, когда: типы и тесты проходят, сборка проходит, сценарий
пройден руками, ни одна кнопка не бездействует, ни одно число не выдумано,
данные переживают перезагрузку, ни один элемент управления не мельче 44
пикселей.

## Git

Отдельная ветка под изменение. Отправка и слияние — только по просьбе
человека. История не переписывается. Сообщение коммита объясняет, что
изменилось и почему. Заметные изменения фиксируются в
[`CHANGELOG.md`](../CHANGELOG.md) (разделы: Добавлено, Изменено, Исправлено,
Безопасность).
