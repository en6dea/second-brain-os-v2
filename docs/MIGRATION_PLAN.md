# Перенос данных из прежней версии

Код: `src/core/migrations/legacy.ts`. Интерфейс: Настройки → «Перенос из
прежней версии».

## Четыре правила

1. Исходный файл не изменяется. Никогда.
2. Перед записью приложение сохраняет собственную копию текущих данных в файл.
3. Сначала предпросмотр, запись только после подтверждения.
4. Нераспознанное поле сохраняется дословно в `legacy`, а не выбрасывается.

## Порядок действий

```
Выбрать файл
   ↓
Разбор: версия схемы, список коллекций, число записей
   ↓
Предпросмотр: что куда попадёт, какие есть предупреждения
   ↓
Подтверждение
   ↓
Копия текущих данных в файл
   ↓
Запись
   ↓
Отчёт: перенесено из скольких по каждому разделу
```

## Откуда берётся файл

Прежнее приложение выгружает состояние целиком: кнопка сохранения копии даёт
`second-brain-backup-ГГГГ-ММ-ДД.json`. Разборщик принимает и объект состояния, и
обёртку вида `{ "state": {...} }`.

### Узкие поля собираются в текст

Запись подсознания в прежней версии состояла из полутора десятков полей:
`theme, question, answer, emotion, trigger, body, thought, fear, cause,
pattern, need, summary, nextStep, promise`. Каждое переносится подписанной
строкой в текст записи, а исходные значения остаются в `legacy`.

Так же собираются люди (обещания, подарки, интересы), идеи и материалы обучения.

### Коллекции без раздела

`actionLog`, `polinaDays`, `polinaWishes`, `polinaPayments`, `coupleActivities`,
`rewardLedger`, `undoStack`, `states`, `folders`, `planningFolders`,
`financeWeeklyReviews`, `budgetPlans` — показываются в предпросмотре с пометкой
«сохранится как есть» и складываются целиком в `legacy` настроек. Ни одна
запись не теряется.

## Преобразования

Суммы умножаются на 100 и округляются: рубли становятся копейками.

Типы счетов: `cash` → наличные, `bank_card` → карта, `deposit` → вклад,
`savings` → накопительный, `credit_card` → кредитная карта, прочее → иное.

Типы операций: `income` → доход, `expense` → расход, `transfer` → перевод,
`refund` → возврат, `adjustment` → корректировка.

Классы расхода: `mandatory` и `required` → обязательный, `needed` и `necessary`
→ нужный, `optional` и `wanted` → желаемый.

Категории операций сопоставляются по названию. Если категории с таким названием
нет, она создаётся.

Отметки привычек переносятся словарём. Значение `true` становится единицей,
число остаётся числом.

Незаполненный остаток счёта остаётся незаполненным. `Счёт.подтверждён`
проставляется только тем счетам, у которых остаток заполнен.

Обязательства: `principalBalance` идёт в тело; если его нет, берётся
`currentBalance`, затем `amount`. Проценты и штрафы переносятся отдельными
полями.

## Что не переносится и почему

Операции без даты пропускаются: без даты операция не может участвовать в
расчёте периода. Их число показывается в предупреждениях, а не умалчивается.

Слой GameLife (опыт, монеты, уровни) не переносится в отдельный раздел. Его
показатели не выводятся из данных, а вторая версия показывает только
посчитанное. Сами записи сохраняются в предпросмотре как нераспознанная
коллекция.

## Отчёт

После записи выводится строка по каждому разделу: сколько перенесено из
скольких, плюс список предупреждений. Пример:

```
Задачи: 83 / 83
Цели: 12 / 12
Привычки: 18 / 18
Операции: 1435 / 1437
Знания: 96 / 96
Люди: 24 / 24
Предупреждения: операций без даты пропущено: 2
```

## Повторный перенос

Перенос добавляет записи, а не заменяет их: запуск дважды создаст дубликаты.
Это осознанный выбор — перенос выполняется один раз. Для повторной загрузки
используйте восстановление из копии второй версии: там сопоставление идёт по
идентификатору и дублей не возникает.
