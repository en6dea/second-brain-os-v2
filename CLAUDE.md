# CLAUDE.md

Постоянный контекст для работы над проектом. Читать перед первым изменением.

## Что за проект

«Второй мозг» — личная операционная система одного человека. Работает в браузере
без сервера, данные лежат в IndexedDB на устройстве.

Вторая версия. Первая живёт в репозитории `en6dea/second-brain-oc` и служит
источником опыта.

## Запрет на прежний репозиторий

`en6dea/second-brain-oc` — рабочая копия, которой человек пользуется каждый день.

Нельзя: изменять его, удалять, переписывать историю, делать принудительную
отправку, использовать как ветку новой версии, переносить туда эту архитектуру.

Читать его для справки можно и нужно.

## Три правила продукта

**Ни одной выдуманной цифры.** Каждое число посчитано из записей, рядом указан
источник. Общего «показателя жизни» не будет: без прозрачной формулы он ничего
не значит. Оформительские `+23%` и `12 инсайтов` запрещены.

**Незаполненное не равно нулю.** `null` означает «неизвестно» и не участвует в
суммах. Ноль означает ноль. Под сводными показателями идёт шкала известного.

**Ни одной мёртвой кнопки.** Если элемент выглядит рабочим, он работает.
Для нерасписанных разделов есть `СтраницаВПлане`: она честно говорит, что будет
и на каком этапе.

## Правила учёта денег

Перенесены из прежней версии, закреплены тестами в
`src/features/finance/model/calc.test.ts`. Менять только вместе с тестами и с
объяснением.

1. Деньги хранятся в копейках целым числом. Рубли только на границе ввода-вывода.
2. Собственные деньги считаются отдельно от кредитных. Кредитный лимит — не ваши
   деньги.
3. Незаполненный остаток счёта не входит в суммы.
4. Перевод между своими счетами не доход и не расход.
5. Платёж по долгу делится на тело, проценты и штрафы. Основной долг уменьшает
   только тело.
6. План не равен расходу. Операция появляется после действия, а не намерения.

## Сохранность данных

Никогда: `localStorage.clear()`, очистка IndexedDB без явной команды человека,
запись пустого состояния поверх существующего, удаление неизвестных полей,
переименование ключей без переноса, сброс данных при обновлении версии.

Перед опасной операцией вызывается `копияПередОпасным` из
`src/core/backup/backup.ts`. Она сохраняет файл до записи.

Поле `legacy` у записей хранит нераспознанные данные прежней версии. Не удалять.

## Архитектура

```
src/
  app/            оболочка, маршруты, навигация, командное окно, быстрое добавление
  core/           предметная область без интерфейса
    db/           Dexie, типы, репозиторий, идентификаторы
    money/        рубли и копейки, запись сумм
    calendar/     даты по-русски
    language/     склонения, запись чисел
    signals/      движок сигналов
    day/          что делать сейчас: одно действие с основаниями
    reminders/    расписание напоминаний из записей
    quick/        разбор команд быстрого ввода
    search/       общий поиск
    backup/       копии и восстановление
    migrations/   перенос из прежней версии
    sync/         договор синхронизации
    demo/         показательные данные
  design-system/  токены и компоненты
  features/       разделы, каждый со своей моделью и страницами
```

Правила:

- Расчёты — чистые функции в `features/*/model/`, без обращения к базе. Их можно
  проверить тестом.
- Каталоги с именами `utils`, `helpers`, `common`, `shared` не создавать. Имя
  модуля называет предметную область.
- Прикладная логика не знает о Firebase и любом другом облаке. Между ними —
  `ПоставщикСинхронизации` из `src/core/sync/provider.ts`. Реализация на
  Firebase — `src/core/sync/FirebaseProvider.ts`, подключается только
  динамическим `import()`, не статическим: SDK весит больше мегабайта, и в
  основной пакет он попадать не должен, что бы ни писалось в этот файл
  дальше.
- Синхронизация не делает исключений по содержимому — всё, что заведено в
  приложении, включая дни в разделе «Отношения» и личные записи дневника,
  попадает в облачную копию после настройки. Единственное устойчивое
  исключение — настройки устройства (per-device, не про приватность):
  `settings` в `src/core/sync/privacy.ts`. Новый код синхронизации проверяет
  таблицу через эту функцию, а не изобретает своё исключение.
- Связи по идентификаторам. Объекты не копируются.
- Файл длиннее 200 строк — повод разделить. Функция длиннее 50 строк — тоже.
- Ранний возврат вместо вложенных условий.

## Именование

Типы, функции и поля предметной области — по-русски: `Операция`, `итогПоСчетам`,
`фактическийОстаток`. Так код читается на том же языке, на котором человек
говорит о своих деньгах.

Имена файлов, каталогов, токенов оформления и внешних библиотек — латиницей.

Весь текст, который видит человек, — по-русски, без иностранных слов.

## Оформление

Направление — «Тихий интеллект», визуальная система — Daylight Observatory:
спокойная, взрослая, точная, с жемчужными поверхностями и сдержанным живым
светом. Вечером доступна тёмно-синяя версия той же системы. Токены в
`src/index.css`. Литеральных цветов в компонентах нет.
Нужного оттенка нет — добавить токен с именем по смыслу.

Темы: светлая, тёмная и «как в системе». Источник выбора — настройки в
IndexedDB. `localStorage` не используется; первый кадр берёт системную тему, а
после чтения базы оболочка применяет сохранённый выбор.

Шрифт один — Manrope. Табличные цифры включаются `font-variant-numeric`, а не
отдельной гарнитурой. Над показанием — единица измерения.

Шкала текста: 12, 14, 16, 20, 24, 32 плюс 11 на единицу над числом. Произвольные
размеры в разметке не писать — только ступени.

Значки: обводка 1.55 и скругления заданы один раз в `index.css`, размеры берутся
из `iconSize.ts`. Цвет значка определяется сущностью, а не страницей: см.
`design-system/components/Icon.tsx`.

Минимальная зона касания — 44 пикселя.

Подробности в `docs/DESIGN_SYSTEM.md`.

## Тексты интерфейса

Кнопка называет то, что произойдёт. Действие сохраняет имя на всём пути.
Пустое состояние объясняет, что делать. Ошибка говорит, что случилось и как
починить, без извинений.

Не писать: «играет ключевую роль», «подчёркивает важность», «в современном мире»,
«не просто X, а Y». Не нанизывать причастия ради глубины. Не выстраивать всё
тройками. Заголовки — обычным регистром, не с Каждого Слова.

## Проверка

Перед завершением работы:

```bash
npm run build   # типы и сборка
npm test        # модульные тесты
npm run lint
```

Этого мало. Запустить приложение и пройти сценарий руками. Ручная проверка уже
находила ошибки, которые типы и тесты пропускали: запись внутри живого запроса
Dexie, `capitalize` на дате, обрезанную сумму на телефоне.

Проверять на трёх ширинах.

## Навигация

Шесть доменов в боковом меню: Сегодня, Планы, Жизнь, Деньги, Знания, Система.
Разделы живут внутри домена и открываются полосой под заголовком. Новый раздел

## Документация

`docs/DEVELOPMENT.md` — единая точка входа в разработку: продукт, стек,
архитектура, модель данных, статус по этапам, ссылки на остальные документы.
Читать в первую очередь при входе в проект без контекста.

Менять `docs/DEVELOPMENT.md` вместе с тем изменением, которое затрагивает
описанное в нём: новый крупный раздел, смена стека, закрытый этап роадмапа,
новая версия. Не копить это отдельным проходом задним числом — правило то же,
что и для `CHANGELOG.md`.

Остальные документы `docs/*.md` — подробности по темам (продукт, данные,
перенос, оформление, план, качество). Меняются, если сами эти темы меняются;
`DEVELOPMENT.md` даёт только выжимку и ссылку на них, не дублирует.

## Работа с git

Отдельная ветка под изменение. Отправка и слияние — только по просьбе человека.
Историю не переписывать. В сообщении коммита — что изменилось и почему.

## Готовность

Изменение готово, когда: типы проходят, тесты проходят, сборка проходит,
приложение запущено и сценарий пройден руками, ни одна кнопка не бездействует,
ни одно число не выдумано, данные переживают перезагрузку, телефон в порядке,
ни один элемент управления не мельче 44 пикселей.
